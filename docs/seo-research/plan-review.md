# Review of docs/SEO-PLAN.md (3 Sep 2026)

Scope: executability of Phase 0 (§4) and Phase 1 (§5.1–5.4), repo accuracy of the plan's citations, and SEO soundness. Items already verified by the caller are not repeated. Evidence paths are relative to `/home/user/Therapylog.github.io` unless prefixed `api/` (= `/home/user/therapylog-api`).

## Lens 1 — Executability

- **blocker** · §5.1(4)–(5), §5.4, §4.3 · `build-pages.js --check` can never be green as specified. `sitemap.xml` takes `<lastmod>` from `git log -1 --format=%cI -- <file>`; the commit that lands the generated output changes every output file's last-commit date, so regenerating after the commit always differs from what was committed (chicken-and-egg), and CI is a shallow clone so every file reports the same commit anyway. Evidence: all five workflows use `- uses: actions/checkout@v4` with no `fetch-depth` (`.github/workflows/validate-compliance.yml:20` etc.); `docs/seo-research/technical.md:113` forbids the obvious escape ("set it from the real content change date, never 'now' on every build"). Fix: have `--check` compare with `<lastmod>` values stripped (or keep lastmod in a committed `scripts/page-dates.json` that the generator updates only when a page's rendered body hash changes), and add `fetch-depth: 0` to the new workflow if git dates stay.

- **blocker** · §5.4 (validate-public-pages), §7, §9 · "no Tier C id anywhere in `tools/` or `markers/`" fails on every generated page: `card` is the Tier C id for Cardarine (§7 list) and `.card` is a CSS class the plan itself inlines (§5.1(1) "`.card .card-title`"); `checkInteractions`, which §5.3 lifts verbatim, renders `<div class="card"` (`app.html:3017`, `:3040`). `mast`, `osta`, `primo`, `npp` are ordinary substrings too. Also, `JSON.parse` of the whole `DB` (287 KB, all 130 entries) or `TL_PK` inlined into a page would carry every Tier C key onto the public page. Fix: define the check as (a) no Tier C key in any data object the generator inlines and (b) no Tier C display name in visible text, and instruct the generator to filter `DB`, `TL_PK`, the injectables array and the interaction pairs through the denylist before inlining.

- **should-fix** · §0 prompt · The prompt orders `node scripts/validate-public-pages.js` and `node scripts/build-pages.js --check` after every phase with "All must exit 0 before you commit", but both scripts are created in Phase 1 (§5.1, §5.4); a literal agent cannot commit Phase 0. Fix: add "once they exist" or create both scripts in Phase 0 with the static page list only.

## Lens 3 — SEO soundness (five objections)

- **should-fix** · §4 item 2 robots.txt · `Disallow: /marketing` and `Disallow: /directory/add-partner` target the two pages that already carry `<meta name="robots" content="noindex">` (`grep -l noindex` → `marketing.html`, `directory/add-partner.html`). A disallowed URL is never fetched, so the noindex is never seen and the URL can still be indexed from links as a bare entry. Fix: delete those two Disallow lines and rely on the meta noindex; `Disallow: /docs/` (and technical.md's `/scripts/`) is moot once `_config.yml` excludes them and only advertises the paths — drop it too. Related nit (§4 item 8): a `<link rel="canonical">` to `/` on `404.html` is meaningless on a 404-status page and can produce "alternate page with proper canonical" noise; give `404.html` `noindex` instead.

- **should-fix** · §4 item 9 title pattern · `<page name> | TherapyLog TRT & Peptide Tracker` produces 63–72-character titles (measured: "Peptide Reconstitution Calculator | …" 68, "Semaglutide Reconstitution Calculator | …" 72, "Free Testosterone Calculator | …" 63). Google truncates around 60 characters / 600 px, so the qualifier meant to disambiguate the occupied brand is exactly the part that gets cut. Fix: `<page name> | TherapyLog` (≤ 50 chars) and carry the qualifier in `Organization.alternateName`, the meta description and the hub H1; or a shorter suffix such as `– TherapyLog Tracker`.

- **should-fix** · §3 / §5.3 per-compound half-life pages · This is 50 programmatic pages with no authored-prose requirement ("SVG curve + the numbers + steady-state math + fact box"), which is the same thin-page shape §3 rejects for interaction pairs. The list includes off-audience drugs (Metformin hl 6, Telmisartan 24, Isotretinoin 21, Rapamycin 62, Raloxifene 27, Levothyroxine 168) and near-duplicate pairs with identical data ("BPC-157" and "BPC-157 Systemic Protocol" both hl 4 est 1; "TB-500" and "TB-500 Systemic Protocol" both hl 48 est 1; Kisspeptin-10 vs Kisspeptin-54). With `DB.mon`, storage rule and interaction rules in the fact box they are compound pages in all but name, shipping in Phase 1 despite §7's "not before the marker pages have four weeks of Search Console data". Fix: cap Phase 1 to the compounds with demonstrated query demand (GLP-1s, three testosterone esters, BPC-157, TB-500, CJC/ipamorelin, HCG, HGH, MT-2, PT-141 — about 15), one page per compound (drop the `*Systemic Protocol` and alias ids), ≥ 200 authored words each enforced by `validate-public-pages.js`, and render the remaining ids as anchored rows on `/tools/half-life-calculator/`.

- **should-fix** · §5.3 compound-specific reconstitution pages · The "200+ words that only apply to that compound, or it is a duplicate" rule is "on the writer" and nothing checks it; the five pages share the same widget, the same "How the math works", the same disclaimer and largely the same FAQs, so the differentiating content is a ladder table and one paragraph. Fix: have `validate-public-pages.js` measure authored words outside the shared blocks (≥ 200) and shingle overlap between sibling pages (< 50%), and require the FAQs on each to name the compound.

- **nit** · §4 item 3 / §5.1(4) canonical–sitemap consistency · Verified consistent: every existing canonical is the extensionless or trailing-slash form the sitemap list uses (`/guide`, `/providers/apply`, `/directory/`, `/providers/`), and the "canonical equal to its URL" assertion covers `?og=1` and `?ref=` variants of tool pages. Keep `/app` (not `/app.html`) in the sitemap, as written. One addition: the `WebApplication` offer should list the annual tier too ($99.99/yr is a locked price in LEDGER §1) or omit prices entirely, so the markup does not contradict `/pro`.
